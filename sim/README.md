# 중력보상 비교 시뮬레이션

실물과 같은 마운트에 팔 하나씩 올린 것 셋을 나란히 세우고, 중력보상 토크에만 서로
다른 계수를 곱해 돌린다. 마운트는 xacro 가 bimanual 일 때만 만들어 주므로 양팔로 뽑은
뒤 한쪽 팔을 지운다 (`model.prune_arm`).

    τ = ratio · G(q)      ratio = 60% (빨강) · 100% (초록) · 140% (파랑)

`ratio` 는 강성이 아니라 앞먹임 토크의 배수다. 목표 자세도 위치 오차도 쓰지 않으므로
강성과 감쇠 gain 은 0 이다 — 실물 모터의 MIT 모드로 치면 `kp=0, kd=0` 에 `τ_ff` 만
보내는 것과 같다.

시뮬레이션에서는 보상에 쓰는 모델과 움직이는 물체가 같은 URDF 에서 나오므로 100% 가
정의상 정확한 보상이다. 실물의 캘리브레이션 값은 쓰지 않는다.

| 비율 | 화면에서 보이는 것 |
| --- | --- |
| 60% | 중력을 다 못 이겨 팔이 처진다. 관절 한계까지 내려가 멈춘다 |
| 100% | 어느 자세에서든 그 자리에 뜬다. 밀면 민 자리에 그대로 선다 |
| 140% | 중력보다 센 토크가 남아 팔이 위로 떠오른다 |

관절마다 실제로 실린 보상 토크를 주황색 화살표로 그린다. 화살표는 관절 축을 따라
놓이고 길이가 토크 크기다. 팔 위의 라벨은 그 팔의 보상 토크 총합을 보여 준다.

## 준비와 실행

    ./setup.sh     # 가상환경 생성 (최초 1회)
    ./run.sh

## 조작

| 키 | 동작 |
| --- | --- |
| `C` | 중력보상 on/off. 끄면 셋 다 똑같이 무너지고, 켜면 셋으로 갈린다 |
| `F` | 세 팔 손끝에 외력 펄스. 누를 때마다 방향이 새로 뽑히고, 세 팔에는 같은 방향이 걸린다 |
| `P` | 손 링크에 페이로드를 얹는다. 플랜트만 알고 보상 모델은 모른다 |
| `R` | 시작 자세로 복귀 |
| `Space` | 일시정지 (MuJoCo 뷰어 기본) |
| `Ctrl` + 오른쪽 드래그 | 마우스로 한 팔만 직접 밀기 (MuJoCo 뷰어 기본) |

`P` 로 얹는 페이로드가 실물에서 보상이 어긋나는 원인이다. 모델이 모르는 질량만큼
중력토크가 더 생기므로, k = 1 로 맞춰 둔 팔도 페이로드를 얹는 순간 처진다. 실물에서
캘리브레이션으로 payload 질량과 무게중심을 찾아 넣는 이유가 여기 있다.

## 설정

모든 값은 `config.py` 한 곳에 있다. 자주 건드리는 것:

- `ARMS` — 비교할 계수와 색
- `START_QPOS` — 시작 자세
- `ARM_SPACING` · `MOUNT_YAW_DEG` — 마운트 간격과 팔이 뻗는 방향
- `CAMERA` — 처음 잡히는 시점
- `REALTIME_FACTOR` — 재생 속도. 0.5 면 절반 속도로 천천히 보인다
- `JOINT_DAMPING` — 관절 감쇠. **제어 gain 이 아니라 모델의 점성 마찰**이고, 실물 관절의
  마찰을 대신한다. 0 으로 두면 정확보상 팔이 한 번 밀린 뒤 영원히 표류한다(물리적으로는
  맞다). 실물의 `kd=0` 조건에 더 가깝게 보려면 0 으로 내린다
- `PUSH_FORCE` · `PUSH_DURATION` — `F` 가 거는 외력의 크기와 길이
- `PUSH_RANDOM_DIRECTION` — 끄면 늘 `PUSH_DIRECTION` 으로 민다
- `PUSH_MIN_VERTICAL` — 뽑은 방향의 위아래 성분 최소 크기. 수평에 가까운 외력만 걸리면
  팔이 옆으로 돌기만 해 보상 차이가 잘 안 보인다
- `PAYLOAD_MASS` — `P` 가 얹는 질량

## 구성

| 파일 | 역할 |
| --- | --- |
| `config.py` | 설정 전부 |
| `model.py` | xacro → URDF 생성, 팔 셋을 붙인 씬 조립 |
| `gravity_demo.py` | 보상 토크 계산, 외력, 뷰어 |

`model.py` 는 xacro 가 만든 URDF 의 visual 메시(collada)를 버리고 collision STL 만
남긴다. MuJoCo 의 URDF 파서가 collada 를 읽지 못하기 때문이고, 관성은 URDF 값을 그대로
쓰므로 중력토크는 달라지지 않는다.
